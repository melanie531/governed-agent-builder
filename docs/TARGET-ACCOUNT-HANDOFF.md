## Callback findings and limitations

Preserved/reviewed interrupted changes provide a non-reflecting HTML recovery page and static rejection categories (missing state/code/cookie, invalid lengths, mismatch). A supported regression shows an older callback must not delete the cookie for a newer sign-in flow. This is a narrow stale-flow recovery fix, not proof of the user's root cause.

Offline HTTP API v2 adapter tests cover raw query, cookie-array transport, Secure/HttpOnly/Lax flow cookie, S256 challenge/verifier, nonce, session creation, replay and invalid callbacks. Existing tests retain issuer/audience/signature/subject, membership and email-verification gates. No state/nonce/PKCE/email_verified checks are relaxed. Real CloudFront cookie/query forwarding, Cognito token exchange, browser navigation, email delivery and target permissions are not cloud-validated here. Investigate only static failure categories and configuration evidence; do not collect raw callback URLs, cookies, codes or tokens.

Security-first / Well-Architected: security is fail-closed target binding and unchanged authentication gates; reliability has offline regressions but still needs real login acceptance; operations has pinned source and reproducible steps, with manual interrupted-stack reconciliation; performance has no new benchmark; cost and sustainability retain the existing serverless design with no new always-on resources. No cloud readiness claim is made.
